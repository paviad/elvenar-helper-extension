# 01 — Haxe runtime shape: how the compiled Elvenar client is laid out and how to hook it

## Scope

This file describes the *mechanics* of the compiled JS bundle (`tmp/elvenar-release-full-reveng.js`,
Haxe 5.0.0-preview.1 → JS): the file wrapper, the runtime registries (`$hxClasses`, `$hxEnums`),
the helpers (`$extend`, `$bind`, `$estr`, `$getIterator`), how classes / interfaces / properties /
enums / abstracts / module-level functions compile, the Haxe std-lib pieces every other document
leans on (`Type`, `js_Boot`, `Reflect`, `Std`, `haxe.ds.*Map`, `haxe.Exception`), the `tink_core`
Future/Promise and `tink_state` reactive layer, the JS↔game bridge (`ExternalUtil`,
`openfl.external.ExternalInterface`, `AS3Communicator`), what the game reads from / writes to
`window`, the entry point (`startElvenar`), and finally exactly what the ElvenAssist extension
relies on from all this (`src/inject/injectMutate.ts`, `src/inject/aviad.ts`, `src/inject/local/*`).

It draws on: the file header (L1-13), `Type`/`js_Boot`/`Std`/`Reflect` (L7069-8260),
`AppMain`/`MainModule` (L4100, L8085), `haxe.Exception` (L366439), `haxe.ds.*` (L428, L694613,
L694689), `tink.core.*` (L380726, L429775, L757521-758700), `tink.state.*` (L380448, L550718),
`de.innogames.shared.util.ExternalUtil` (L658601), `FLGlobal` (L7407),
`openfl.external.ExternalInterface` (L7014), `AS3Communicator` (L3762) and
`com.innogames.as3communicator.io.javascript.JavaScriptConnector` (L132550), the console command
plumbing (L391881-391975), the file tail (L760798-787964).

Package-level orientation is in `02-package-map.md`; DI/bootstrap/commands/events in
`03-bootstrap-di-commands-events.md`; networking in `04-networking-layer.md`; the extension's hook
mechanics in full detail (min-build anchors, XHR/WebSocket interception) in
`06-extension-hooks-and-recipes.md` — §10 below covers only what depends on the runtime shape.

## 1. File wrapper and the two snapshots

The **shipped** bundle (`tmp/elvenar-release-full-20260314.js`, and the `elvenar-release-min-*.js`
the live site normally loads) is one big IIFE:

```js
// Generated by Haxe 5.0.0-preview.1+2c1e544
(function ($hx_exports, $global) { "use strict";
$hx_exports["Reflect"] = $hx_exports["Reflect"] || {};
var $hxClasses = {},$estr = function() { return js_Boot.__string_rec(this,''); },$hxEnums = $hxEnums || {},$_;
function $extend(from, fields) { ... }
...
})(typeof exports != "undefined" ? exports : typeof window != "undefined" ? window : typeof self != "undefined" ? self : this,
   typeof window != "undefined" ? window : typeof global != "undefined" ? global : typeof self != "undefined" ? self : this);
```

So in the browser **`$hx_exports === window` and `$global === window`**. Everything else —
`$hxClasses`, `$hxEnums`, every `var pkg_Class = function…` — is a *closure-local* of that IIFE
and is **not reachable from the page**. That single fact is why the extension has to rewrite the
script text before it runs (see §10).

The **reveng snapshot** (`tmp/elvenar-release-full-reveng.js`, the file all line numbers in these
docs point into) is the same code with the IIFE opened up for analysis: lines 2-3 are
`var $hx_exports; var $global;`, line 5 is `"use strict";`, and the last line (L787964) is a lone
`}`. The class index `rev-eng/index/classes.tsv` was built against the reveng file.

## 2. Registries and helpers

### `$hxClasses` — the class registry (L7)

Every class and interface is registered right after its constructor:

```js
var de_innogames_onyx_city_model_ApplicationModel = function() { … };            // ctor
$hxClasses["de.innogames.onyx.city.model.ApplicationModel"] = de_innogames_onyx_city_model_ApplicationModel;
de_innogames_onyx_city_model_ApplicationModel.__name__ = "de.innogames.onyx.city.model.ApplicationModel";
```

Mapping rule FQ name → JS identifier: `.` → `_`, and a `$` is inserted for Haxe *private module
types* (`haxe.ds._StringMap.StringMapValueIterator` → `haxe_ds__$StringMap_StringMapValueIterator`,
`tink.core._Future.SyncFuture` → `tink_core__$Future_SyncFuture`). `classes.tsv` column 3 gives the
identifier so you never have to derive it.

Who *reads* `$hxClasses` (the whole list — `Type.resolveClass` does **not** exist in this build,
DCE removed it):

| Consumer | Line | Note |
|---|---|---|
| `api.ClassName.toClass` (abstract) | L89305 | `$hxClasses[name.split("<")[0]]` |
| `away3d.utils.Cast.tryClass` | L131824 | asset class lookup with cache |
| `haxe.NativeStackTrace` stack parsing | L416036 | strips a leading `$hxClasses.` from stack frames |
| `haxe._Unserializer.DefaultResolver.resolveClass/resolveEnum` | L693325 | `haxe.Unserializer` |
| `openfl.Lib.getDefinitionByName` | L706768 | Flash-API shim |
| `openfl.net.SharedObject` (class-alias resolution) | L732042 | |
| `openfl.system.ApplicationDomain.getDefinition/hasDefinition` | L732232 | |
| `de.innogames.onyx.city.inventoryitems…CraftingViewModel.getCraftingViewModelConfig` | L55859 | the one place *game* code does a by-name lookup: `$hxClasses["de.innogames.onyx.city.inventoryitems.model.IInventoryItemConfigModel"]` guarded by `!= null` (feature-optional class) |
| `Type.resolveEnum` | L7071 | `$hxEnums[name]` (enum twin) |

Only classes/interfaces/enums are registered. **Abstracts** (`tink_core_Future`, `openfl_Vector`,
`api_ClassName`, `tink_state_State`…) and **module-level functions** are plain closure vars and are
*not* in `$hxClasses` (§4.4, §4.5).

### `$hxEnums` — the enum registry (L7)

`$hxEnums = $hxEnums || {}` (note the `||` — it survives a second bundle load). Enums register
inline: `var pkg_E = $hxEnums["pkg.E"] = { __ename__:"pkg.E", __constructs__:null, …}` (§5).
Consumers: `Type.resolveEnum` (L7071), `Type.typeof` (L7115), `js_Boot.__string_rec` (L7206),
`js_Boot.__instanceof` (L7319), `haxe._Unserializer.DefaultResolver.resolveEnum` (L693328).

### `$estr` (L7)

`function() { return js_Boot.__string_rec(this,''); }` — installed as `toString` on every enum
value so `String(enumValue)` prints `CtorName` or `CtorName(p1,p2)`.

### `$extend(from, fields)` (L8)

```js
function $extend(from, fields) {
	var proto = Object.create(from);
	for (var name in fields) proto[name] = fields[name];
	if( fields.toString !== Object.prototype.toString ) proto.toString = fields.toString;
	return proto;
}
```

Used for every subclass prototype: `Sub.prototype = $extend(Super.prototype, { …own fields… })`.
Consequence: `Sub.prototype` is a *fresh object whose [[Prototype]] is `Super.prototype`*, so
patching `Super.prototype.method` after load affects subclasses that did not override it, and
`instanceof` works normally.

### `$bind(o, m)` (L760799)

```js
function $bind(o,m) { if( m == null ) return null; if( m.__id__ == null ) m.__id__ = $global.$haxeUID++;
  var f; if( o.hx__closures__ == null ) o.hx__closures__ = {}; else f = o.hx__closures__[m.__id__];
  if( f == null ) { f = m.bind(o); o.hx__closures__[m.__id__] = f; } return f; }
```

Haxe emits `$bind(this,this.onFoo)` wherever a method is used as a value (event listeners,
callbacks). It **memoises** the bound function per (object, method): the method function gets a
numeric `__id__`, the object gets a `hx__closures__` map, and the same bound closure is returned
every time — that is what makes `removeEventListener(type, $bind(this,this.onFoo))` work. Side
effects you will see when inspecting objects: `hx__closures__` on instances, `__id__` on method
functions (and on any object used as an `ObjectMap` key, §6). `Reflect.fields` deliberately hides
`__id__` and `hx__closures__`.

Because the closure is cached, **replacing `X.prototype.method` after an instance has already
bound it does not affect already-registered listeners** — they hold the old bound closure. Patch
prototypes before the game constructs things (i.e. in the script-rewrite phase) when the method is
used as a listener.

### `$getIterator(o)` (L760798), `$arrayPush` (L760800), `$_` (L7)

`$getIterator` wraps arrays into `haxe_iterators_ArrayIterator` for `for (x in iterable)`. `$_` is a
shared scratch temp used in expression-position constructs (`($_=new X(), $bind($_,$_.m))`, and in
enum constructor definitions).

## 3. Class shape

A typical concrete class (`de.innogames.onyx.city.model.ApplicationModel`, L10635-10745):

```js
var de_innogames_onyx_city_model_ApplicationModel = function() {   // constructor: field defaults + super call
	this._mapLength = 0; … this._isGameLoaded = tink_state_State._hx_new(false);
	de_innogames_onyx_mvcs_BaseActor.call(this);                    // super(...)
};
$hxClasses["de.innogames.onyx.city.model.ApplicationModel"] = de_innogames_onyx_city_model_ApplicationModel;
de_innogames_onyx_city_model_ApplicationModel.__name__ = "de.innogames.onyx.city.model.ApplicationModel";
de_innogames_onyx_city_model_ApplicationModel.__interfaces__ = [de_innogames_strategycity_main_model_ITickObject];
de_innogames_onyx_city_model_ApplicationModel.__super__ = de_innogames_onyx_mvcs_BaseActor;
de_innogames_onyx_city_model_ApplicationModel.prototype = $extend(de_innogames_onyx_mvcs_BaseActor.prototype,{
	gameLoaded: null            // every instance field is declared on the prototype as null
	,injector: null             // (injected fields look identical — null until the injector fills them)
	,get_isLoading: function() { return this._loading; }
	,set_isLoading: function(value) { return this._loading = value; }
	,postConstruct: function() { … }
	,__class__: de_innogames_onyx_city_model_ApplicationModel
	,__properties__: {set_season:"set_season",get_season:"get_season",…}
});
```

| Slot | Where | Meaning |
|---|---|---|
| `var X = function(args){…}` | ctor | field defaults, then `Super.call(this, …)`. Static classes with no ctor still get `var X = function() { }` |
| `X.__name__` | static | FQ dotted name (string) |
| `X.__super__` | static | superclass ctor (absent for root classes) |
| `X.__interfaces__` | static | array of interface ctors (only when non-empty) |
| `X.__isInterface__ = true` | static | interfaces only; their prototype lists each method as `null` and has `__class__` |
| `X.__properties__` | static | static getters/setters map (`{get_instance:"get_instance"}`), e.g. `JavaScriptConnector.__properties__` L132553 |
| `X.prototype = { … }` / `$extend(Super.prototype,{…})` | | instance fields (as `null`), methods, `__class__`, `__properties__` |
| `X.prototype.__class__` | | back-pointer to the ctor. **`Object.getPrototypeOf(o).__class__.__name__` (or simply `o.__class__.__name__`) is the FQ class name of any Haxe object** |
| `X.prototype.__properties__` | | instance property→accessor map; subclasses do `__properties__: $extend(Super.prototype.__properties__, {…})` (e.g. `MainModule` L8140) |
| `X.STATIC = …` | L780137+ | static fields are assigned in the tail block, not next to the class |
| `X.staticMethod = function…` | right after `__name__` | static methods sit between the registration and the prototype |

`__class__` is also stamped on natives: `String.prototype.__class__` (non-enumerable, L760805),
`Date.prototype.__class__` (L760809). Arrays have no `__class__`; `js_Boot.getClass` (L7189) special-cases
them.

Field visibility does not exist at runtime: private Haxe fields are plain properties (conventionally
`_name`). Injected fields (Robotlegs) are ordinary null-initialised prototype fields; the injector
assigns them via the `MacroReflector.factories` table (§9).

### 3.1 Properties: `get_x` / `set_x`

Haxe `var x(get,set)` compiles to **method calls at every use site** — there are no JS
accessors (only 2 `Object.defineProperty` calls in the whole file, both unrelated). So:

- reading `model.isLoading` in Haxe is `model.get_isLoading()` in JS; writing is `model.set_isLoading(v)`;
- the *backing* field is whatever the getter reads (usually `_x`);
- `__properties__` (2,995 prototypes + 156 statics carry one) is only metadata for
  `Reflect.getProperty/setProperty` (L8183/L8202) — those look up `o.__properties__["get_"+field]`
  and call it, else fall back to `o[field]`. `Reflect.getProperty`/`setProperty` are the two
  functions the bundle **exports** to the page as `window.Reflect.getProperty/setProperty`
  (`$hx_exports["Reflect"]`, L6/L8183/L8202).
- Interfaces list their properties too (`IChestsModel` L10625 has
  `__properties__: {get_flexibleChests:…}`), so `Reflect.getProperty(anIChestsModel, "flexibleChests")` works.
- `Type.getInstanceFields` (L7108) enumerates prototype keys minus `__class__`/`__properties__`.

Practical rule for the extension: **call `get_x()` / `set_x(v)`, never read `x`** (reading `x` on a
property-backed field yields `undefined`, since only `_x` exists). `aviad.ts` already types
`aviad_am.get_isLoading()` and `aviad_se.diplomacyCosts.get_resources()` this way.

## 4. Other type kinds

### 4.1 Interfaces
`var I = function() { }; $hxClasses["…I"] = I; I.__name__ = …; I.__isInterface__ = true; I.prototype = { m1: null, …, __class__: I }` (e.g. `openfl.events.IEventDispatcher` L14-25, `haxe.IMap` L411). An interface that extends another gets `I.__interfaces__ = [Parent]` (`tink.core.OwnedDisposable` L429855). Interfaces are used as **DI keys** (`injector.getInstance(de_innogames_onyx_shared_effects_IEffectsProvider)`, L55861) — resolvable via `$hxClasses["…IEffectsProvider"]`.

### 4.2 Static-only classes
`var X = function() { }` + `X.__name__` + static methods; no meaningful prototype (`Type`, `Std`, `Reflect`, `Str`, `FLGlobal`, `ExternalUtil` L658601, `UncaughtErrorBuffer` L86023).

### 4.3 Enums — see §5.

### 4.4 Abstracts (`abstract X(T)`)
Compile to a bare object holding static functions whose first parameter `this1` is the underlying
value; **not registered in `$hxClasses`**, no `__name__`. There are ~220 (`grep -c '^var [A-Za-z_$]* = {};$'`).
Important ones: `openfl_Vector` (L880), `ASAny`/`ASObject`/`ASDictionary` (L3791-3963, AS3
compatibility shims), `FastXML` (L7498), `UInt`, `UnicodeString` (L86040),
`api_ClassName` (L89302), `tink_core_Callback` (L380726), `tink_state_Observable` (L380448),
`tink_state_State` (L550718), `tink_core_Future` (L757521), `tink_core_Promise` (L758382),
`tink_core_Next` (L758692), `tink_core_Lazy`, `tink_core_Signal`. Their "constructor" is `X._hx_new(...)`
(e.g. `tink_state_State._hx_new(false)`), and property-style access is `X.get_value(v)`.

### 4.5 Module-level functions and vars (Haxe 5)
Top-level Haxe functions compile to hoisted `function pkg_Module_fn(...) {}` statements —
238 of them, e.g. `de_innogames_common_utils_InjectionUtil_nextTimeTypeIsAvailable(injector,type,getInstance)`
(L138658), `de_innogames_onyx_constants_ApplicationModuleName_getId(module)` (L512524),
`de_innogames_onyx_city_model_ApplicationModel__createModuleStateMachine(states, injector)`
(private, double underscore, called from `ApplicationModel.postConstruct` L10696),
`de_innogames_onyx_shared_calculator_premium_PremiumCalculatorUtil_calculateCraftingTimePremiumCost`
(L55853). Same for module-level vars (`de_innogames_onyx_city_ancientwonders_views_gallery_states_HandleResourceState_normalSkin`,
L380757). They are not in any index; find them with `grep -n '^function de_innogames_'`.

| Piece | Meaning |
|---|---|

| `E.__empty_constructs__` | the parameterless ones (singleton values) |

| `v._hx_index` | how *all* generated `switch` statements dispatch: `switch(state._hx_index) { case 0: … }` (L380757); the case number is the declaration position — read the enum definition to decode |

`tink.core.Outcome` (`Success(data)`=0 / `Failure(failure)`=1, L758194), `tink.core.FutureStatus`

`enums.tsv`.

Extension usage: `src/inject/local/localOpenAw.ts` does
`window.aviad_enum['de.innogames.onyx.shared.events.LoadType'].LOAD_ONLY(buildingId, baseName)` and
hands the result to `new AncientWondersDataEvent('displayAncientWonder', playerId, loadType, 'window_0')`.

## 7. `haxe.Exception` (L366413)

`haxe_Exception` extends the native `Error` (`__super__ = Error`, `prototype = $extend(Error.prototype, …)`).
Fields: `message`, `__previousException`, `__nativeException`, `__skipStack`, `stack`; methods
`unwrap()`, `get_message()`, `get_native()`, `get_stack()`, `toString()`. Statics:
`haxe_Exception.caught(v)` (wraps anything thrown into a `haxe_Exception`/`haxe_ValueException`)
and `haxe_Exception.thrown(v)` (used at every `throw` — returns the native `Error` for
`Error`s so the browser gets a real stack). Game exception classes extend it, e.g.
`de.innogames.onyx.cashshop.exceptions.BridgeException` (L366499). Uncaught page errors are
buffered by `UncaughtErrorBuffer` (L86023: `window.errorBuffer`, `window.onerror`) until the logging
bootstrap flushes them (`FlushUncaughtErrorBuffer` L391982, which then sets `window.onerror = null`).

### 9.2 How callbacks are wrapped

- A future is **consumed** with `future.handle(function(v){…})` — the instance method — regardless of
  whether it is a `FutureTrigger`, `SyncFuture` or `SuspendableFuture`. Haxe inlines
  `tink_core_Future.handle(f, cb)` to exactly that (L757532). For a `Promise`, `v` is an `Outcome`:
  check `v._hx_index == 0` then use `v.data`, else `v.failure` (a `tink_core_TypedError` with
  `message`, `code`, `data`).
- A future is **produced** either with `var f = new tink_core_FutureTrigger(); …; f.trigger(value); return f;`
  (10 sites, e.g. `SpireEffectSelectionAnimationHandler.animateCardsDropIn` L628097 wrapping a
  TweenMax `onComplete`), or with `tink_core_Future.irreversible(function(callback){ … callback(v) … })`
  (7 sites, e.g. `BitmapDataConverter.convertTextureMetaData` L589890) — the latter is *lazy*: nothing
  runs until someone calls `.handle()` or `.eager()` (`Future.async` calls `eager()` for you).
- `Promise._hx_new(f)` (L758386) adapts a `(resolve, reject)` pair; `Future.ofJsPromise` (L757665)
  adapts a native `Promise`.
- Because `handle()` on a `Ready` future invokes synchronously, calling `.handle` from the console on
  an already-resolved future runs your callback immediately.

## 10. What the ElvenAssist extension relies on from this layer

All of this is in `src/inject/injectMutate.ts` (runs in the MAIN world before the game script):

1. **Intercept the loader.** The page's inline `function loadGameCode(){…}` contains the bundle URL
   (`…/elvenar-release-(min|full)-<hash>.js`). The extension blanks that function body, fetches the
   bundle itself (`fetchAndModify`), rewrites the text, and injects it as an inline `<script>`.
   `window.gameVars.gameScriptUrl` records the URL.
2. **Leak the registries.** `hookRegistry('var d={},', 'var $hxClasses = {},', 'aviad')` turns
   `var $hxClasses = {},$estr = …` into `var $hxClasses = {};window.aviad=$hxClasses;var $estr = …`;
   likewise `$hxEnums = $hxEnums || {},` → `…;window.aviad_enum=$hxEnums;var …` (min build:
   identifiers `d`, `Ab`/`vb`). After this, **`window.aviad["fq.Name"]` is the class ctor and
   `window.aviad_enum["fq.Enum"]` the enum object** — the exact objects the game uses, so
   `new window.aviad['de.innogames.onyx.worldmap.service.WorldMapService']()` is a real service
   (typed in `src/inject/aviad.ts`), and patching `window.aviad['X'].prototype.method` patches the game
   (comment block at the bottom of `injectMutate.ts` shows the `BuildBuildingSectorMode.placeBuilding` example).
3. **Capture instances by patching constructors** (`patchCtorRegistryAssignment`). For a class
   `X` it renames the ctor `var X = function(a,b)` → `X2aviad=function(a,b)` and, at the
   `$hxClasses["fq"] = X;` line, re-defines
   `X = function(a,b){ X2aviad.call(this,a,b); window['<field>']=this; (window['<field>_a'] ||= []).push(this) };`
   before the registration — so every construction records `window.<field>` (latest) and
   `window.<field>_a` (all). This works only because the ctor is a plain `var X = function` and the
   registry assignment is a separate, greppable statement, and because `X.prototype = …` is assigned
   *after* the registration line (the replacement function object is the one that later receives
   `.prototype`, `__name__`, `__super__`, statics). Currently hooked:

   | window field | Class | Used by |
   |---|---|---|
   | `aviad_am` | `de.innogames.onyx.city.model.ApplicationModel` (L10650) | `aviad_am.injector.getOrCreateNewInstance(cmdCtor)` to instantiate commands with injection; `get_isLoading()` |
   | `aviad_wm` | `de.innogames.onyx.spire.views.windows.diplomacy.SpireDiplomacyWindowMediator` | spire diplomacy `_onInvest` |
   | `aviad_se` | `de.innogames.onyx.spire.wrappers.SpireEncounter` | `diplomacyCosts.get_resources()` |
   | `aviad_ts` | `de.innogames.onyx.networking.services.TreasureService` | |
   | `aviad_tv` | `de.innogames.onyx.city.treasure.model.TreasureViewModel` (L80872) | `getTreasures(type)` |
   | `aviad_silm` | `de.innogames.onyx.city.engine.snake.components.layers.SnakeInteractiveLayerMediator` | `isoEngine.dispatchEvent(new IsoDecorationEvent(...))` |
   | `aviad_pagination` / `_a` | `de.innogames.onyx.shared.ui.components.pagination.Pagination` | `localNextPage.ts` |

   Caveat of this technique: it does not fire for instances that already exist (none do — the
   patch runs before the script), and subclasses that call `Super.call(this)` *do* go through the
   patched function (so `aviad_am` would also catch subclasses of `ApplicationModel`, if any).
4. **Grab a return value inside a method** — the regex on `_createCameraController: function(){…return X;}`
   (which lives in `de.innogames.onyx.city.controller.bootstrap.ConfigureIsoEngineCommand`, L390539)
   inserts `window.aviad2 = X;` before the return, exposing the `CityCameraController`.
5. **Identify objects at runtime by class name.** `src/inject/local/localNextPage.ts` filters
   `Object.getPrototypeOf(r.parent).__class__.__name__ === 'de.innogames.onyx.shared.ranking.views.tabs.tabbodies.PlayerRankingBody'`
   — relying on the prototype `__class__` back-pointer (§3). Note this is *different* from the
   `__class__` string field the extension reads out of **network JSON** (`response.__class__ === 'ServerResponseVO'`
   in `src/inject/socketResponses.ts`, `PlayerRankingVO` in `localProcessRankingsData.ts`): that
   one is a wire-format discriminator the server sends, not the Haxe prototype slot.
6. **Enum construction** as in §5 (`localOpenAw.ts`).
7. **Property calls**: `aviad_am.get_isLoading()`, `aviad_se.diplomacyCosts.get_resources()`,
   `resource._value` (a bigint-backed value object read directly), per §3.1.
8. **`wrapOne(v, name)`** (`window.wrapOne`, `src/inject/shadowProxy.ts`) wraps a ctor in a `Proxy`
   whose instances log every method call when `window.aviadlog` is truthy — a generic tracing aid
   for any `aviad['…']` class.

### 10.1 Recipes that follow from the runtime shape

- **Find a class by name at runtime:** `aviad['de.innogames.onyx.city.model.ApplicationModel']`
  (or `Object.keys(aviad).filter(k => /Service$/.test(k))` to browse). Interfaces are there too and are
  what `injector.getInstance(...)` wants.
- **Class of any object:** `o.__class__.__name__`; superclass chain:
  `o.__class__.__super__.__name__`; interfaces: `o.__class__.__interfaces__.map(i=>i.__name__)`.
- **Is-a check the Haxe way:** `aviad['js.Boot'].__instanceof(o, aviad['de.innogames.onyx.mvcs.BaseActor'])`
  (also handles interfaces).
- **Property-aware read/write of an object you only know by field name:** `Reflect.getProperty(o,'isLoading')`
  (that global is the game's exported one, §8.2).
- **Enum value → name:** `v.__enum__` gives the enum FQ name, `aviad_enum[v.__enum__].__constructs__[v._hx_index]._hx_name`.
- **Read a StringMap:** `map.h` is a null-prototype dictionary; `Object.entries(map.h)`.
- **Bound listener identity:** if you need to remove a game listener you did not add, the listener
  the game registered is `o.hx__closures__[o.method.__id__]`.
- **Static constants** (event type strings, ids): read from the ctor object, e.g.
  `aviad['starling.utils.HAlign'].LEFT`; they were assigned in the tail block.
